# WP-21 report: CLI AI layer

## Summary

- `config.py`: `STAGES`, routing defaults (section 14.6), `load_config()` with precedence `--model` > env `GTJOB_MODEL_<STAGE>` > `gtjob.toml [models]` > default. `model_for(stage, escalate=True)` moves a Haiku *default* to Sonnet (user overrides are never escalated). `max_tokens()` reads `briefs.budgets()["stages"]` (a fix re-run takes `max(stage, fix)`). `[thinking]` in `gtjob.toml` is off unless set (`true` or a token budget ≥ 1024).
- `llm.py`: `LLMClient` protocol, `AnthropicClient` (`output_config` json_schema with `schemas.api_schema`, 3 retries with exponential backoff on 429/5xx and connection errors, refusal and `max_tokens` errors, case-insensitive enum normalization, usage mapping), `FakeClient` (canned responses per stage, records prompts, synthetic usage). Missing key raises `E_API_KEY` (exit 3) with the required hint.
- `cache.py`: `.cache/gtjob/llm/<sha256>.json`; the key covers model, system, history, blocks, schema, max_tokens and thinking budget. `--no-cache` skips reads and still writes.
- `prompts.py`: `build_prompt` takes `briefs.build_packet` and splits it into block 1 (system: preamble + Core rules), block 2 (`digest.txt`, only for match/tailor), block 3 (header, inputs, reply, output). `cache_control` goes after blocks 1 and 2. Interactive runs use the 1h TTL on both (the API forbids a longer TTL after a shorter one). Critic PNGs are attached only with `visual`. `build_fix_prompt` wraps the `fix` packet.
- `stages.py`: `run_stage` and `run_stage_checked`. The check runs in-process through `cvtlib.cli.main([...,"--json"])` with captured stdout. On exit 1 the retry is a new user turn (the fix packet) after the replayed original turn and the model's previous file, with the same system blocks so the cache prefix is reused. Other non-zero exits raise at once. Every API call appends `kind: api` to `usage.jsonl` (cache hits make no call and write no row).

## Deviations

- `max_attempts` counts total model calls (default 2: the first answer plus one fix re-prompt), not fix re-prompts. `cvt brief fix` still enforces its own `max_fix_attempts`.
- `cvtlib.briefs.build_packet` is used instead of the `build_brief` string wrapper, because the packet carries `visual`, the digest-split inputs, the cache-hit result and the warnings.
- For the fix retry the stage is the stage being run (not `FIX_TARGETS`). The whole stage output file is rewritten from the model's reply. If the failed check left no failing state (`E_NOTHING_TO_FIX`), the fix packet is built from the violations in the check's JSON envelope.
- A `jd` cache hit (`find_cached_jd`) skips the API call. If the check then fails, the fix turn quotes the current file, since there is no original turn to replay.
- Thinking is per stage in `gtjob.toml [thinking]` (`true` = 1024 tokens or an explicit budget); it adds to `max_tokens`.
