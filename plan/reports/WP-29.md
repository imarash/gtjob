## Deviations and decisions

- `guide_core` raises `CvtError(CHECK_FAILED, "E_GUIDE_NO_CORE")`: `ExitCode` has no `VALIDATION`; exit 1 is the closest.
- `guide_core` returns the Core body without the `## Core` heading line.
- Hidden-bullet hint is `(+N bullets hidden; cvt brief <stage> RUN --item ID)` (step 3 wording; the 14.3 example omits `RUN`;
  `RUN` is optional on the CLI, so both work).
- Attestation lines follow 14.3 exactly, so `placement` is not shown. Guides must tell the model to cite only attestations
  whose placement allows it (a wrong placement is caught by the `placement` rule). Suggest adding it in a future contract change.
- `build_packet` returns a `Brief` dataclass (packet, est_tokens, budget, cache hit, warnings, attempt); `build_brief` is the
  contract wrapper returning the Markdown. Both accept `--visual` via `build_packet(visual=)`.
- `profile_digest` takes extra keyword-only args (`stage`, `today`, `full_ids`, `excerpt_chars`) so the tailor stage can force
  strong/partial evidence in full and tests are clock-independent.
- Highlight fill stops at the first highlight that does not fit ("until the budget is reached"). A 110-char reserve per fill
  covers the parent-line hint a hidden bullet adds.
- `digest.txt` is written at the first match brief (kept afterwards) and overwritten, re-filled, by the tailor brief. The questions
  packet builds its header lines from the profile directly rather than reading `digest.txt` (same lines, no staleness).
- Fix attempts are counted in `out/<run>/briefs/fix-attempts.json` keyed by (failed command, last success index in
  `state.history`); a passing rerun resets it. `assemble` therefore records its own history event on success, and renames the
  `check-tailored` failure event to `assemble` so the next action reruns `assemble`.
- The fix packet recomputes violations for `jd-check`, `match-check`, `profile-build` (schema level) instead of persisting them;
  tailored/plan failures come from `validation.json`. Plan violations use `t-...` item ids so the fix packet can map them to plan elements.
- `assemble`: plan-level violations (`plan_ref`, `skill_unsupported`) write only `validation.json` (no `tailored.json`). Provenance-only
  violations write `tailored.json` and go through the WP-13 path, which versions it and fails.
- `assemble` failure output on stderr is at most 10 lines and its last line is `hint: ... cvt.py brief fix RUN`.
- Skill resolution order: skill groups (stop on first hit), then highlights (up to 3), then attestations with matching `terms` and a
  skills placement. The golden fixture agrees (e.g. `Docker` -> `skl-1` only).
- `education.details` is the whole profile education `text` when `include_details` (no thesis field exists in the profile).
- Seed requires the candidate run's profile sha to equal the current one, otherwise item ids may not map.
- `[N]` indexes in change requests use `diff.diff_items(tailored, profile, None)` order when `diff.py` is present, else bullet order.
- Attested bullets accept active attestations plus this run's proposed ones (same as `provenance`).
