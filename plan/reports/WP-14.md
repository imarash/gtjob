# WP-14 report: page fit, ATS round-trip, keyword coverage, `validate`

**Status: DONE.** No contract changes, no escalation.

## Summary

- `fit.py`: `drop_order` (section 9 order) and `fit_run`: density pass (comfortable, standard, compact), then a binary
  search on `k` at `compact`. Search compiles go to `build/fit-try.pdf`; `cv.pdf` holds only the final render.
  `MAX_RENDERS = 24` includes the final compile (one is reserved), and exceeding it is exit 7 (`E_FIT_RENDER_CAP`).
  Priority-1 overflow is exit 1 (`E_FIT_OVERFLOW`) with the section 9 message verbatim.
- `ats.py`: `extract_pdf_text` (`pdftotext -layout`, else pypdf, NFKC) and `ats_check`. It reports `ats_missing`
  (name, email, website, section titles, employers), `ats_order` (section order, first bullet before its employer
  heading), and `ats_garbage` (`(cid:`, U+FFFD, text under 90% of the model's non-space characters).
- `coverage.py`: per-requirement found/missing keywords (keyword plus JD synonyms, case-insensitive, no word-boundary
  false hits such as `helmet` for `helm`). `WARN_BELOW = 0.70`.
- `validate.py`: all ten gates in section 10 order, `validation.json`, `final/<Name>-<Title>[-<Company>].pdf`, state
  (`validation`, `final_pdf` artifacts, stage `validated` on a non-draft pass). The `layout` gate (section 14.5) uses
  `pdftotext -bbox`, else pypdf (fill ratio only). Every warning names its page (`item_id: page-N`).
- `commands/fit.py`: `fit RUN [--png]` and `validate RUN [--draft]`. Human output is at most 10 lines for validate.

## Deviations and choices

- Drop order tie-break for units without an employer date (skill groups, certifications): at equal priority they drop
  after dated bullets, so skill keywords and credentials survive longest. Among them, later position drops first.
  The brief does not say; this is the only place it is decided (`fit.UNDATED_RANK`).
- `fit` stage: sets `rendered` only when the run is at `approved` or later (same rule as `render`). With the run's
  `--draft` option the command is allowed from `tailored`, and the stage stays put.
- `validate` is allowed from `tailored` only for draft validation (needs `fit.json` and `cv.pdf`). A draft pass never
  moves the stage and never writes `final/`; its `next_action` says so.
- Orphan heading check: last `ORPHAN_HEADING_LINES = 2` lines of a non-final page, but only the very last line of
  the final page (a short closing section like Certifications is legitimate there). Needs `pdftotext -bbox`.
- Footer lines (page number) are excluded from the layout check: lines whose top is inside the bottom margin.
- Placeholders and attestation-status gates use `draft` only (the stage is always at least `rendered` when run).
- `validate` failure raises `E_VALIDATION_FAILED` (exit 1) with the failing violations; the stage stays `rendered`,
  `status` becomes `failed`. `validation.json` is always written.
- `ats_check(..., jd)`: `jd` is accepted for the contract signature but unused (the gate compares PDF with model).
- `cvtlib.profile.merged_view` and `attestations.usable` are not called directly: `provenance.check_tailored`
  already applies both internally. `attestations.load_store` supplies the store.
- `ruff` is not installed in this checkout, so no lint run beyond the test suite.
