# WP-19 report: match report (`report`) and `critique-save`

Status: DONE

## Summary

- `cvtlib/report.py`: `build_report(run_dir)` returns Markdown from run artifacts alone. It has 13 sections in the
  brief's order, then `## Token usage` last. `jd.json`, `match.json` and `tailored.json` are required (missing means
  exit 4, `E_ARTIFACT_MISSING`). Everything else is optional and gives a "not run" / "not recorded" / "not rendered"
  line.
- `cvt report [RUN]` writes `report.md`, records the `report` artifact, and sets the stage to `reported` when the
  stage is ≥ `validated`. Otherwise it writes the report with a "Draft report" banner and leaves the stage.
  Output is 4 lines (report path, pdf, gate summary, token total). `--json` is supported.
- `cvt critique-save RUN FILE` takes plain JSON or Markdown (the first fenced block starting with `{`, preferring
  ```` ```json ````). It validates against `critique.schema.json`, checks `tailored_version` against the current
  `tailored.json`, and writes `critique.json`. It records the artifact and never changes the stage. Output is one
  line per criterion plus a verdict line. Invalid input exits 1 and leaves any existing `critique.json` untouched.
- Coverage: "covered by a confirmed fact" means a cited, usable attestation (active, or proposed in this run) whose
  `terms` match a requirement keyword or which appears in the requirement's match evidence. Such requirements are
  marked "→ confirmed (att-NNN)" and are excluded from Remaining gaps.
- Source issues are resolved when a usable `correction` attestation targets one of the issue's `item_ids`.
- Recruiter asks appear only in their own section. `jd.noise` text is never echoed. Injection flags are quoted
  one-line in their own section only.

## Deviations

- The brief says unconfirmed gaps get "not added, as you didn't confirm it". A `partial` gap that the CV already
  half-supports (for example req-5) gets the same sentence. A rejection recorded in `answers.json` adds "You answered
  that you don't have it."
- The `critique-save` `run_id` is not compared with `state.run_id`. The contract fixtures use free-form `run_id`
  values, and `tailored_version` is the checked field.
- With API rows present, the total row uses actual API input and ignores packet estimates, to avoid double counting.
  With packets only, the total is the estimate and is labelled so.
- `report` is written with a plain `write_text`, not an atomic replace (`jsonio` has no public text writer).

## Open issues

- When a gate is not yet recorded (`validation.json` absent) the "Found in PDF" column reads "not validated".
- "Items to confirm" repeats `open_items` of kind `gap` and `source_issue`, which also show in the dedicated
  sections. This follows the brief's wording.
- `commands/report.py` calls `report.final_pdf` and `report.token_summary`, which are public but not in the frozen
  `interfaces.md` signature (only `build_report` is). No contract change is needed.
