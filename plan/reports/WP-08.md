# WP-08 report: run commands (`init`, `status`)

## Summary
- `cvt init`: exactly-one-JD-source check (exit 2, `E_JD_SOURCE`), CV validation (exit 5; `.docx` exits 5 with
  hint "export to PDF or paste text"), `--host` override, then `state.create_run`. Human output is 3 lines
  (`run:`, `dir:`, `next:`). `--json` data is `{run_dir, run_slug, inputs}`.
- `cvt status [RUN] [--all]`: human output is at most 8 lines (header with slug, stage, status, checkpoints and
  pending count; the first 3 pending prompts truncated at 80 characters; stale artifact names; the last error; a
  `tokens:` line when `usage.jsonl` exists; `next:`). `--json` data is `{state (summary), pending_questions
  [{id,prompt,default}], tokens?}`. With `--all`, `state` is the full state and `runs` lists every run newest first.
  Exit 4 with the `cvt init` hint when no run exists.
- `hostdetect.detect()`: `CLAUDECODE` -> `claude_code`, any `CURSOR_*` -> `cursor`, otherwise `unknown`
  (best-effort, documented in the module docstring).
