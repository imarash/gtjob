## Deviations

1. Acceptance command 5 uses `-q` with five paths. This git (2.42) rejects that ("`--quiet` is only valid with a
   single pathname"). I ran it without `-q`, redirecting stdout to `/dev/null`. The ignore rules are correct.
2. `--json` and `--all` are added to each subparser after all commands register (`_Subparsers.finalize`), not through
   `parents=[...]`. Command modules call `add_parser` themselves and may define their own `--all`
   (`status --all`, `approve --all`, `lint-skill --all`). A `parents` copy would raise a conflicting-option error.
   Behavior matches the brief: both flags work before or after the subcommand (SUPPRESS default on the subparser copy,
   tested). A command's own `--all` keeps its meaning and shares `args.all`.
3. `usage_totals()["total_est"]` is the sum of packet estimates only. The contract does not say whether it also
   includes API actuals. API figures are under `["api"]`.
4. A failed run's `next_action` uses "brief fix" when the last `errors[]` code is in
   `state.CHECK_FAILED_ERROR_CODES = ("E_SCHEMA", "E_CHECK_FAILED")`. Otherwise it uses "Fix the reported problem".
   The rerun command is the last history event, else `status`. The contract's `add_error(st, code, message)` has no
   exit-code field, so this is how exit 1 is told apart. Later WPs should use `E_CHECK_FAILED` when recording
   exit-1 errors.
5. `jsonio.load_json` raises `E_FILE_NOT_FOUND` / `E_FILE_UNREADABLE` (INPUT) for missing or unreadable files.
   `E_JSON` is used for syntax errors, as specified. `validate-artifact` checks that the target exists first and
   reports `E_ARTIFACT_MISSING` (exit 4).
6. Extra helpers beyond the listed API: `schemas.to_violations`, `output.cap_list`, `output.cap_lines`,
   `output.MORE_LINE`, `usage.usage_path`.
7. `validate-artifact` always resolves RUN, even with `--file`. An unknown NAME exits 2 (`E_SCHEMA_UNKNOWN`). Any of
   the 15 schema names is accepted, not just the 12 in the command table.
