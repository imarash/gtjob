## Deviations (all within the contract's intent)

1. `questions.check` takes optional `jd=` and `profile=` keyword arguments (for link existence and requirement-keyword
   suppression). The positional signature is unchanged. Suppressed entries come from `questions.suppress`, which `check`
   calls; the command reports them in `data.suppressed`.
2. A gap choice whose `value` is a requirement ID (`req-N`) suppresses by that requirement's keywords. `--select` then
   uses the label as the single term (never the ID). Normal values are `term|synonym`.
3. `--select` on a `scope_confirm` question builds a `confirm_scope` item (not `choose`), so the selection takes effect.
4. `commit_round` assigns the stored round number itself (max existing + 1); the AI's `round` value is ignored.
5. The scope skeleton's `links.attestation_ids` is `["pending"]`. At commit it is filled with the attestations created
   from the same parent question, narrowed by the quoted claim in the prompt, then by identical scope items.
6. Extra truthfulness checks on rounds (violations, exit 1): `verbatim` must be an exact part of `raw_text`; numbers in
   claim/terms/detail/new_value must appear in `raw_text`; `terms` non-empty (not for corrections); corrections
   need `type correction` + `correction_only` and a real profile item.
7. A `role_label`/`items` scope that matches nothing is stored as `unresolved` (candidates skeleton, exit 6).
8. `--select` also accepts a choice label (case-insensitive) for a choice ID, because the Claude Code option shape
   carries no IDs; its question text starts with `[q-N]`.
9. One scope skeleton is produced per round item and distinct scope (so SLOs and error budgets, two items, give 2).
10. Claude Code `free_text` questions get two options (default, Skip) because the tool needs ≥ 2.

## Open issues

- `questions --add` accepts a bare list or `{"questions": [...]}`; the guide for `brief questions` (WP-29) should say which.
- `answers-apply --commit` does not itself add the skeleton questions; the AI must run `cvt questions RUN --add` first
  (as specified). Without them, scoped attestations are still created, and unresolved ones keep the run at exit 6 with
  a message naming the missing scope question.
