# WP-17 report: `classic` template

Status: DONE (`sidebar` variant skipped, see Deviations).

## Summary

Added `classic.typ`: single column, Libertinus Serif, centered small-caps name, italic headline, one contact line with
links. Section titles are small caps with a thin full-width rule (still real `heading` elements, so the PDF stays tagged).
Entry heads reuse `common.typ` (employer bold left, dates right; italic title, location right), with indented
client subentries and tight bullets. Body size, margins, leading, and section gap come from `presets.json`. Black text,
rules in dark gray `#222222`. Metadata, `[[CONFIRM: …]]` draft highlight, and the page footer reuse `common.typ`
(`draft-highlight`, `page-footer`). No `eval`; data is inserted as text.

## Tests cover

Both fixtures compile with `classic` through `write_build` / `compile_pdf` (junior 1 page, senior at `compact` ≤ 3 pages);
all fonts embedded and named Libertinus; PDF title/author metadata; section order and employer + dates on one line
(pdftotext, skipped if absent); markup-like strings render literally; draft footer and `[[CONFIRM]]` text present only
when `meta.draft`; template source contains no `eval(` and reads only the two contract inputs.

## Deviations

- `theme.accent` is intentionally unused (black text and `#222222` rules, per brief "black text only").
- `common.typ`'s `section-title` is modern-styled and `render-section` calls it, so `classic.typ` redefines both locally
  (same dispatch logic) rather than editing `common.typ`, which it does not own.
- `sidebar.typ` skipped (optional). `render.TEMPLATES = ("modern", "classic")` would also need updating to expose it.

## Open issues

- Small caps make `pdftotext` (non-layout) split the name onto two lines ("Jamie" / "Rivera") because of mixed glyph
  sizes. Text is intact and in order and pypdf extracts it fine, but an ATS that is sensitive to this might prefer `modern`.
