## Behaviour decisions (not contradicted by contracts)
- **Stage handling.** `diff` only moves `tailored`/`awaiting_approval` runs (→ `awaiting_approval`, `cp2: pending`;
  auto → `review: auto`, `approved`, `cp2: skipped`). A run already at `approved` or later is only read. `approve` never
  lowers a later stage.
- **`apply-edits` with `approve_all` and nothing pending** goes to `approved` and runs the same finalization as `approve`
  (activates this run's proposed attestations with resolved scopes, sets `attestations_used`, `cp2: done`).
  Otherwise it goes to `awaiting_approval`. Without this, the golden `edits-001.json` would leave `att-001` proposed
  at stage `approved`, and the `attestation_status` gate would fail.
- `apply-edits` copies the edits file to `edits/NNN.json` only **on success**. A rejected batch leaves no files and marks
  state `failed` with the error.
- `apply-edits` keeps IDs stable and does not renumber. New bullets get `max+1`, placed in profile order.
  `check-tailored` renumbers later, as before. `version` = max(current, last snapshot) + 1. A missing snapshot of the
  old version is written first, so `diff --against previous` always works.
- Provenance runs with `draft=True` (proposed attestations of this run are usable); placeholders are not blocking.
  Schema and logistics checks also run on the result.
- `reject` of a rewritten/merged/attested bullet restores the original only when exactly one bullet-level ref exists
  **and** no other bullet already cites it. Otherwise it drops the bullet. Without that guard, the golden attested bullet
  `t-exp-1.b4` would duplicate `t-exp-1.b3`. Reject also covers the summary (single `sum-N` ref) and `t-header`
  (profile `basics.label`).
- `approve` on a role or engagement cascades to its bullets. A role or engagement with bullets settles to `approved`
  once none of its bullets is pending, so `pending_ids` lists leaves only (`t-sum`, skills groups, bullets, `t-earlier`).
- `replace_text` and `restore` set `review: pending`, so the user sees the change before `approve`.
  `replace_text` on a role sets its intro line. The earlier line has the ID `t-earlier`; `drop t-earlier` sets
  `include=false`. `set_field paper` is validated only; the command writes `template`, `page_target` and `paper` to
  `state.options`.
- `approve` without `--all` and with pending items exits 6 (`E_PENDING_ITEMS`, violations list the IDs) and moves a
  `tailored` run to `awaiting_approval`. Proposed attestations with `scope.kind: unresolved` stay proposed and are
  listed in `data.unresolved`.
- Compact `diff` shows the outline, then `kept (not listed): N bullets, M other items`, then one line per changed item.
  On the junior golden it is 21 lines. `--full` lists every item. `--format json` follows the same split.

## Deviations
- `diff` and `apply-edits` bodies are exempt from the 15-line human cap (`output.emit` with `all=True`) because the
  brief requires the diff body (< 40 lines compact). JSON `data.items` is not capped at 10: capping would hide changed
  items. Excerpts keep it small. `approve` follows the normal caps.
- `render_diff_md` has an extra keyword `compact=False`; the contract signature still works as written.
- Items carry extra keys `origin` and, for dropped items, `note` (the omission reason); the JSON adds `n`.
