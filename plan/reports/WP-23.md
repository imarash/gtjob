## Deviations

- WP-21/WP-22 were not built when I wrote this, so `gtjob.stages/llm/config` and `gtjob tailor/continue` are used by
  contract only. `stage_env` (conftest) builds `(AnthropicClient(), config, run_stage)` from the first of
  `gtjob.config.load_config | load | Config`, and skips with a reason if the names differ. **Integration (I-4) must check
  that factory name and the `run_stage` return value (the `answers.round.json` path).**
- `followup_skip` is set up with the canonical exchange, not the ambiguous Kafka case. Skipping an unresolved-scope
  question leaves the attestation unresolved and `answers-apply` exits 6, so only canonical follow-ups can reach exit 0
  (matches WP-20 step 5). Verified deterministically in `test_replay_followup_skip_after_canonical`.
- `answers-apply` does not create scope follow-ups itself; the harness adds the dry-run `skeletons` with
  `cvt questions --add` before `--commit`, as a host agent does.
- Full-pipeline final-CV checks run only for `canonical` and `edit_earlier` (per the brief). The `rejection` and
  `ambiguous_scope` `final_cv`/`forbidden_terms_in_final_cv` expectations are not run live.
- The baseline is judged on the five text criteria; `visual` and `questions` have no baseline equivalent.
- Token budget counts each stage's budget once, however many API calls it took (retries count against it).
- Trigger test flags: `claude` 2.1.20 has no `--max-turns`; the session is bounded by `--tools Skill,Read`,
  `--max-budget-usd 0.50`, and an early stop at the first trigger. Verify flags with `claude --help` on newer versions.
- `from conftest import ...` in `tests/integration/test_wave3.py` would pick up `evals/conftest.py` if `tests` and `evals`
  are collected in one session, so `evals/conftest.py` defines the same names (`HOME_ENV`, `HOST_ENV`, `REPO_ROOT`,
  `SKILL_DIR`, `CVT_PY`). Default `pytest` (testpaths `tests`) is unaffected.

## Open issues

- Live runs need a key. Expect small assertion drift on the first run (for example `answer_parse` needing the right
  `old_value` for corrections; the commit step reports that as a violation).
- `gtjob tailor --answers` uses `q-1` as the free-text target for the canonical/Helm replies; if the model's gap question
  is not `q-1`, `--answers` would exit 2 (unknown id) and the evals would fail with that message.
